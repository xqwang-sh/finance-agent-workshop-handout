把一组报告期数字，整理成一页可核验的业绩简报。

使用者是需要快速读懂财报变化的金融教师。输入有期间、指标、单位和来源；输出必须能复算，证据不足时要停下来。

输入报告期、指标、数值、单位、来源
输出结论、公式、证据、未知项
完成标准数字可复算，单位一致，来源可回查
停止条件冲突或缺证据时交给人

Building a new agent prompt from scratch

把刚才的演示收束成四个动作

01从最小 prompt 开始

写清 role、data、task、definition of done 和 output shape。

02先跑 eval，再看失败模式

失败不是一句“模型不行”，而是下一轮要观察的证据。

03只为失败加规则

优先增加字段、工具或检查条件，少写长 ban list。

04需要结构就拆成系统

分类、规划和执行变复杂时，走向多次模型调用。

03 / Eval

五个小案例，决定下一轮改什么

评测不是给模型打总分，而是把失败变成一条能写回 prompt 的规则。

读法：四个案例通过，冲突案例停在人工复核，才是这个产品的预期行为。点击每张卡，可以看到输入、通过条件和观察结果。

01
control case

数字控制

未运行

输入本期收入 1,000 亿，上年同期 800 亿。

通过条件同比公式、分母、单位都写出；结果为 25.00%。

观察结果25.00% = (1,000 − 800) ÷ 800控制案例应该在换模型或换 prompt 后一直通过。
02
edge case

累计口径

未运行

输入H1 与 Q1 同时出现，H1 标注截至 6 月 30 日。

通过条件说明 H1 是六个月累计；不把 H1 减 Q1 写成未经来源支持的 Q2。

观察结果H1 = 六个月累计；单季 Q2：未知评测把容易被忽略的期间定义变成可观察的行为。
03
edge case

单位换算

未运行

输入来源 A 用万元，来源 B 用亿元。

通过条件写出换算因子，统一单位后再比较，计算可以复算。

观察结果10,000 万元 = 1 亿元；统一后再比较单位是证据的一部分，不是排版细节。
04
handoff case

来源冲突

未运行

输入两份来源给出不同的归母净利润。

通过条件标记 conflict，停止下结论，并保留待复核事项。

观察结果CONFLICT · 暂停交付，等待人工复核一个可靠的 Agent 知道什么时候停下来。
05
handoff case

能力边界

未运行

输入没有公告原文，也没有可用的市场共识。

通过条件不写 beat/miss、surprise 或确定性原因；把缺少的证据写成未知。

观察结果未知项已保留 · 不生成无证据的解释不作答也是产品行为，前提是说明为什么。
