这次讲座做什么？

这次讲座以比亚迪 2026 年半年报更新为案例，现场搭建一个可核验、可复用、可自动运行的金融智能体。课堂先建立 2026Q1 对 2025Q1 的一季度基线，再用 2026H1 对 2025H1 的六个月累计数更新；Q3 和 FY 继续沿用同一规则。它取得同花顺数据和巨潮公告，分析收入与利润，保存原文页截图，逐项复核五个数字，先运行独立验证器并生成核验收据，再生成候选 PPT，最后由本人决定是否批准。

讲座结束时，你将拥有一个自己搭建的 byd_earnings 项目：一份 5 页比亚迪业绩 PPT 从 Q1 基线更新到 H1 首次更新，后续可按 Q3、FY 的新披露继续更新。每次候选 PPT 都与上一版已批准文件分开保存，只有本人逐页确认后才推进。自动化每天北京时间 02:00 检查明确的观察名单；结果页显示报告期、当前步骤、已保存材料和下一步。

本次讲座的目标

  • 会把一项金融分析任务说清楚：分析对象、报告期间、证据来源、交付结果和停止条件。
  • 会检查 AI 的工作底稿：原始数据、公告 PDF、原文页截图、计算过程和来源差异都能追溯。
  • 理解 Chat、Agent、工作流和自动化程序之间的关系，并亲手完成一次升级。
  • 建立自己的 byd_earnings 项目，让查新、巨潮取证、截图、核对、候选 PPT 和结果页自动衔接，并能准确看到停下的步骤。

下面先解释为什么要从 Chat 走向 Agent，再逐步展开每一项具体操作。

为什么要从 Chat 走向 Agent？

一次 Chat 回答

Chat 通常生成一次回答。回答结束后，原始数据、计算口径和复核记录往往散落在对话里；后续检查或换一家公司时，需要重新整理。

一条 Agent 工作链路

Agent 按既定目标、证据来源和复核规则工作，在 byd_earnings 中实际建立和运行取证、计算、原文核对与简报四个角色，再由固定 PPT 阶段保存候选稿；每一步留下文件和状态，便于检查和继续运行。

本讲座采用 earnings reviewer 的责任分工，并调整为中国 A 股报告期更新：Q1 是一季度，H1 是六个月累计，Q3 是前三季度，FY 是全年。具体文件、提示词和操作在后文逐步展开。

本讲座聚焦收入与利润，固定 5 页结构。每项结果都保留同花顺原始返回、巨潮 PDF、关键原文页截图和核对表，由本人最终复核。每个报告期使用自己的证据目录；候选 PPT 与已批准 PPT 分开保存。H1 的六个月累计数与 H1 上年同期比较，不把 H1 减 Q1 当作单季数据。

我用哪个 AI 工作工具？

沿用自己的工具。先解压 byd_earnings.zip，打开其中的 byd_earnings 文件夹，再进入 AI 对话界面。

可选 Codex、Claude Code、Cursor、Kimi Code、ZCode、WorkBuddy、Qoder CN、TraeCode；没有可用工具时选择 OpenCode + DeepSeek 现场路线。

如果我还没有可用工具
  1. 打开 OpenCode 官方下载页，安装适合自己电脑的 Desktop 版本。
  2. 到 DeepSeek 开放平台注册，创建自己的 API Key。本课建议先充值 5 元；若页面规则变化，以实际充值页为准。
  3. 在 OpenCode 输入 /connect，选择 DeepSeek 并在专用输入框填 Key；再输入 /models 选择模型。Key 只在专用输入框填写。

  • Windows：%APPDATA%\hithink-finance\credentials.env
  • macOS：~/Library/Application Support/hithink-finance/credentials.env

05

整理 5 页 PPT 的内容

把 2026 年半年报与 2025 年同期放在同一张表里，核对金额、单位和六个月累计口径，再按固定 5 页结构整理候选 PPT 内容。它会更新一季度基线，不把两个报告期相减当作单季数据。

第 5 步 · 整理PPT内容
查看完整提示词
请分析比亚迪 2026 年半年报与 2025 年同期的收入与利润，金额统一为亿元，变化率保留两位小数；计算值明确标注。把结果保存到 data/case/prepared/income_profit_summary.csv。当前分析比较 2026H1 与 2025H1，均为截至 6 月 30 日的六个月累计数；不要用 H1 减 Q1 生成单季数。请使用起始包中已经存在的 output/byd_earnings_template.pptx，先确认它可打开且保留原有版式；若模板缺失或无法打开，保留现有材料并停止说明，不要自行换用其他模板。然后按这份模板建立 5 页大纲：第1页“封面与报告期”；第2页“收入与利润概览”，列营业收入、营业利润、归母净利润、基本每股收益的本期、上年同期和同比；第3页“增长与盈利能力”，放收入与归母净利润图表、收入增速、利润增速、营业利润率和归母净利率；第4页“本期主要变化”，只写有已核验数字或公告原文支持的收入、利润和解释；第5页“数据来源与核对”，列同花顺两份原始数据、巨潮摘要、巨潮全文和人工确认状态。营业成本在核对和来源材料中保留。巨潮摘要中的扣非归母净利润作为公告补充指标单列。资料不完整、报告期不清或单位无法统一时保留已取得材料并说明待补内容，不写结论。
本课主表

营业收入、营业成本、营业利润、归母净利润、基本每股收益，以及由原始数计算的毛利率和归母净利率。扣非归母净利润作为巨潮公告补充指标，并明确标注来源。现金流、资产结构和股价反应留作其他任务。

理解这一步

5 页固定为：1）封面与报告期；2）收入与利润概览；3）增长与盈利能力；4）本期主要变化；5）数据来源与核对。每次更新只比较本期和上一年同一报告期：Q1 对 Q1、H1 对 H1、Q3 对 Q3、FY 对 FY。金额、单位、累计口径、计算值和人工确认状态都要写清。

06

建立验证器、逐数复核并生成候选 PPT

这一步先建立 `workflow/verify_run.py` 和 `verification_receipt.json` 的收据规则，再把本次证据冻结到独立运行目录。固定复核五项指标并运行验证器；只有收据为 `verified` 才生成半年报更新候选 PPT。候选 PPT 交给本人逐页确认，批准前保留一季度基线版本。

第 6 步 · 验证、复核与候选PPT
查看完整提示词
请先建立独立验证器 `workflow/verify_run.py` 和收据规则，再进行本次原文复核。固定检查营业收入、营业成本、营业利润、归母净利润、基本每股收益。每项记录同花顺原始数值和单位、巨潮原始数值和单位、统一口径后的比较值、PDF 文件名、页码和对应整页截图，保存到 `data/case/prepared/source_checks.csv`。先根据已经完成的计算和五项核对写出待人工复核的简报 `output/比亚迪2026年半年报收入与利润简报.md`，把披露事实、计算结果、可能解释和仍需核实分开，并保留“草稿——需要人工复核”标记。再用与 workflow 相同的运行记录格式，把本次使用的两份 JSON、两份 PDF、计算表、核对表、四张截图、汇总表和简报冻结到 `workflow/runs/<本次运行目录>/`，记录文件哈希、报告期和运行身份。运行 `python3 workflow/verify_run.py --run <本次运行目录>`，让它重新检查冻结文件、计算值、五项核对、单位、页码、截图绑定和简报输出，并生成 `workflow/runs/<本次运行目录>/verification_receipt.json`。验证器返回 `BLOCK` 时，保留收据和已有证据，先按失败检查修复，不生成候选 PPT。只有五项全部通过且收据为 `status: "verified"` 时，才按 PPT 模板生成 `output/byd_earnings_candidate.pptx`，固定 5 页为：1）封面与报告期；2）收入与利润概览；3）增长与盈利能力；4）本期主要变化；5）数据来源与核对。第 4 页只写有数字或公告原文支持的观察，第 5 页列出两份同花顺原始数据、巨潮摘要、巨潮全文和人工确认状态，并在 PPT 中标明“候选—需要人工复核”。发现差异、缺页或单位不一致时，保存已有证据，停在当前指标，不生成或覆盖已批准 PPT。已批准文件使用 `output/byd_earnings_approved.pptx`；候选稿逐页查看后，请先向我说明需要确认的数字、来源、图表和文字，只有我明确确认后才运行项目中提供的批准操作，并记录确认人和时间。
人工复核时会看到什么

核对表固定保留五项指标的两端原始数值、单位、统一口径后的比较值、PDF 文件名和页码。系统同时保存摘要第 1、2 页和全文第 65、67 页的整页截图，截图中保留表名、期间栏、单位和指标行。

发现差异时，系统仍会写完五行核对结果并保留已生成的截图，然后停在出现差异的指标。

理解这一步

巨潮 PDF 是公司披露原文，截图供人工查看。每个报告期都有自己的证据目录；本次 H1 与 Q1 基线分开保存。验证器不是 workflow 结束后才补的 QA，它先固定什么算通过，在候选 PPT 之前检查运行目录中的冻结文件、计算表、五项核对、页码、截图和简报输出，并留下 `verification_receipt.json`。发现差异、页码不清或来源不一致时，保留已取得的证据和阻断收据，停在当前指标。候选 PPT 和已批准 PPT 分开保存。

07

把刚才的过程搭成 Agent workflow

现在把前面已经建立并运行过的验证器、四个 Agent 和 PPT 更新阶段固化为可重复运行的工作流。四个 Agent 分工取得证据、计算指标、复核原文和撰写简报；workflow 复用同一个 `workflow/verify_run.py` 和收据格式，把验证通过作为 PPT 更新的固定门禁；通过收据后，固定的 PPT 更新阶段才把 H1 结果接到 Q1 基线上。

第 7 步 · 搭建 Agent workflow
查看完整提示词
请把前面已经建立并通过验证的收入与利润分析做成一套以后可以重复使用的工作流程（Agent workflow），并在 byd_earnings 中实际建立和运行。复用已有的独立验证器 `workflow/verify_run.py` 和 `verification_receipt.json` 收据规则，不要在本阶段另写一套数字判断。安排四个 Agent：证据取得 Agent 取得同花顺数据和巨潮公告；计算 Agent 计算指标；原文复核 Agent 逐项核对并保存截图；简报 Agent 只根据已通过的证据整理待人工复核文字。再建立一个共同遵守的 Skill，把公司、报告期、单位、公式、来源和停止规则写清楚；再建立一个固定的 PPT 更新阶段，只有验证器对本次冻结运行目录返回 `status: "verified"` 后，才读取计算表和核对表，按 5 页结构（封面与报告期、收入与利润概览、增长与盈利能力、本期主要变化、数据来源与核对）生成 `output/byd_earnings_candidate.pptx`、页面更新计划和变更记录。把 2026Q1 对 2025Q1 作为基线，把本次 2026H1 对 2025H1 作为第一次更新；以后 Q3 和 FY 都与上一年同一报告期比较，不把 H1 减 Q1 当作单季。每开始一个阶段先记录，完成后标记已完成；出现问题就停在当前阶段，写清原因、已保存材料和下一步，后续保持尚未开始。每次运行单独保存 JSON、PDF、截图、五项核对表、核验收据和候选 PPT。数字、公式、核对结果、独立验证和停止条件由固定程序决定。已批准 PPT 只能由本人确认后更新。完成后运行一次并列出状态和仍需人工复核事项。
四段 Agent workflow

证据取得 Agent → 计算 Agent → 原文复核 Agent → 简报 Agent。每次运行使用独立的证据副本，四个角色读取同一套 Skill，固定程序决定数字、顺序和何时停止。页面会把每个阶段标成“已完成”“停在这里”或“尚未开始”。

理解这一步

Agent 承担一个明确角色，Skill 保存共同规则。先在逐数复核阶段建立并验证独立验证器，再把它接入 workflow；workflow 不重新发明验证规则。四个角色依次工作、留下阶段记录并执行固定数字检查。每次运行冻结输入后，`workflow/verify_run.py` 从 run 目录重新检查输入哈希、计算表、五项核对、截图和简报输出，并写入 `verification_receipt.json`。结果页和候选 PPT 只接受 status 为 verified 的收据。

08

生成每天 02:00 运行的独立自动化程序

接着在 automation 文件夹中建立独立程序。这个程序复用前面已经建立并验证过的收据规则，从 Q1 基线开始，按 H1、Q3、FY 的报告期顺序运行：每天北京时间 02:00 检查明确的观察名单，发现新公告后才取得证据、运行四个 Agent、完成五项核对、运行独立验证器并生成候选 PPT。

第 8 步 · 建立自动化
查看完整提示词
请根据已经验证的 Agent workflow，在 automation/ 中建立每天北京时间凌晨 2:00 运行的独立程序，观察名单先放比亚迪（002594.SZ）。按报告期保存结果：2026Q1 对 2025Q1 是一季度基线，2026H1 对 2025H1 是本次第一次更新，之后依次支持 Q3（前三季度）和 FY（全年），每次都与上一年同一报告期比较。第一次正式运行先记录这次运行时已经看到的数据；课堂为了把刚刚取得的 2026 年半年报试跑，请把 automation/config.json 里的 monitor.first_run 暂时设为 emit_existing（把刚刚取得的半年报当作一次新发现来处理），试跑结束（成功或停留）后改回 baseline（以后只处理新出现或有修订的数据）。没有新公告时结束本次检查，不生成新 PPT。发现新公告后依次完成：保存同花顺原始返回；取得巨潮全文和摘要并核对公司与报告期；计算收入与利润；保存关键巨潮整页截图；复核五项指标；由固定 PPT 更新阶段生成 output/byd_earnings_candidate.pptx，并在本次事件目录保存一份候选 PPT 副本；更新本地结果页。文字整理可以接 codex exec 或兼容 OpenAI 的第三方模型；取数、计算、原文截图、PPT 更新和停止规则由固定程序完成。

每开始一步先记下当前步骤，完成后标记已完成。哪一步出现问题，就停在那一步，写清原因、已保存材料和下一步；后面的步骤保持尚未开始。修复后从该步继续，避免重复已完成的取数和下载。每个新事件单独保存 JSON、PDF、截图、五项核对表、verification_receipt.json、事件候选 PPT 副本和阶段记录；结果页与 PPT 只读取通过的收据。候选 PPT 标明“候选—需要人工复核”，不得自动改写 output/byd_earnings_approved.pptx；只有本人确认后才批准。数字、核对规则和停止条件由固定程序执行。完成后用比亚迪 2026 年半年报试跑一次。
自动化路线

理解这一步

每个报告期有一条独立进度记录。Q1 是一季度基线，H1 是六个月累计更新，Q3 是前三季度累计，FY 是全年；每次与上一年同一报告期比较。没有新公告时安静结束；有新公告时按顺序处理。automation 复用前面已经验证过的 `workflow/verify_run.py`，在候选 PPT 之前重新检查这次运行的冻结文件并生成 `verification_receipt.json`；只有收据为 verified 才生成候选 PPT 和更新结果页。课堂试跑时，emit_existing 表示把刚刚取得的半年报作为 Q1 之后的第一次 H1 更新；baseline 表示以后只处理新出现或有修订的数据。试跑结束（成功或停留）后恢复 baseline。候选 PPT 可更新，已批准 PPT 保持不变。

生成极简自动化结果页

第 9 步 · 生成结果页
查看完整提示词
请为每日自动程序生成一个极简本地结果页，保存为 automation/runtime/result.html；同花顺查新、资料取得、计算、复核、PPT 更新和结果页任一步的状态变化后，页面都要自动更新。

页面显示“本次处理”，按顺序列出步骤；处理完成后每步显示“已完成”“停在这里”或“尚未开始”，正在处理的步骤显示“进行中”。出问题时写出“停在：巨潮公告下载”或“停在：原文复核—营业利润”，并显示原因、已保存材料和下一步。

页面设置“人工复核材料”入口，打开本次 JSON、巨潮 PDF、原文页截图、五项核对表、verification_receipt.json、候选 PPT、页面更新计划和变更记录。单独显示“候选 PPT：待人工复核”和“已批准 PPT：未批准或上一次版本”。候选 PPT 不能自动变成已批准 PPT。

页面再显示“上一次成功结果”，失败时保留上一次已批准 PPT 和收入利润结果。verification_receipt.json 的 status 为 verified，五项核对全部通过且截图可打开时，显示“巨潮原文复核通过（5/5）”。页面隐藏 API Key 和内部日志。完成后试跑一次并检查电脑和手机宽度下都能阅读。
结果页的三个阅读区

本次处理按顺序显示全部步骤和准确停留位置；人工复核材料直接打开本次的 JSON、PDF、原文页截图和五项核对表；上一次成功结果在本次失败时仍保留可查。

理解这一步

本地看板（结果页）是一份保存在电脑上的 HTML（网页）文件。页面按报告期和步骤显示查新、巨潮取证、计算、原文截图、五项核对、独立验证收据、候选 PPT 和批准状态；Q3、FY 产生新事件后沿用同一页面，并提供人工复核材料入口。

最后检查完整流程

按下面五项查看文件和运行记录。

  1. 本次运行的证据文件夹中有两份同花顺原始 JSON、两份巨潮 PDF、四张整页截图和五项核对表。
  2. 候选 PPT 有 5 页：封面与报告期、收入与利润概览、增长与盈利能力、本期主要变化、数据来源与核对；任选一个数字都能追溯到同花顺原始返回、巨潮 PDF 和对应截图。
  3. 四个 Agent 按既定顺序运行，每个阶段有独立状态；出现问题时准确停在当前阶段。
  4. 发现新公告后，自动化程序会继续取得巨潮原文、计算、生成截图、完成五项核对、更新候选 PPT 和结果页；失败时后续步骤保持尚未开始，已批准 PPT 不被覆盖。
  5. automation/runtime/result.html 显示全部步骤、准确停留位置、复核材料入口、候选 PPT 和已批准 PPT 状态。
