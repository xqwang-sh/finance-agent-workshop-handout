从Chat到Agent：金融智能体搭建入门

用一页业绩简报理解产品、做法与评测；真实数据与自动化作为进阶扩展

先用一个本地教学输入做出一页业绩简报，再用五个小测验比较 Chat、固定 workflow 和生成—评测—修复。主线完成后，真实 Hithink/CNINFO 数据、5 页候选 PPT、四 Agent workflow、查新和结果页作为进阶扩展。

先看产品真实数据指南

先看产品，再看怎么证明它可靠

这次讲座先做一个小而完整的产品：把一组报告期数字整理成一页可核验的业绩简报。课堂用“产品 → 做法 → 评测”的顺序，让第一次接触 Agent 的人先看见交付物，再理解为什么需要 workflow 和生成—评测—修复。

主线五步只使用本地教学输入，完成一页候选简报和五个评测；完成后可选择进阶扩展，把同一接口接到真实 Hithink/CNINFO 数据、候选 PPT、四 Agent workflow 和自动化结果页。

使用者

需要快速阅读业绩变化的金融教师。

输入

本期、上年同期、单位、指标、来源和不确定项。

输出

一页简报、评测报告、未知项和人工复核状态。

本次讲座的目标

  • 能把一个金融分析产品说清楚：使用者、输入、输出、完成标准和停止条件。
  • 能用五个小评测检查数字、累计口径、单位、来源冲突和能力边界。
  • 能比较一次 Chat、固定 workflow、生成—评测—修复三种做法，并跑通一个最小闭环。
  • 知道怎样把同一套接口扩展到真实数据、候选 PPT、四 Agent workflow 和自动化结果页。

为什么先做一个小产品？

一次 Chat

一次 Chat 可以很快写出一版文字，但输入、计算、检查和未知项常常混在一条回答里。它适合作为基线，让我们看见产品哪里可能出错。

一个 Agent 产品

一个 Agent 产品把目标、输入、输出、评测和停止条件写清楚，再按固定顺序留下文件。它不要求一开始就搭出完整自动化，而是先把一个小闭环跑通。

主线只讨论收入、利润、同比、单位、报告期和证据边界；不做投资建议，也不写没有输入支持的共识比较或原因。真实公司材料、凭据和自动化都在进阶区。

五个评测分别检查数字、累计口径、单位换算、来源冲突和能力边界。通过条件先写下来，失败时保留报告并停在需要修复的位置。

三种做法怎么比较？

一次 Chat

先生成一版，速度快，检查点少；它是基线。

固定 workflow

把生成、检查和交付拆成固定顺序，每一步有明确产物。

生成—评测—修复

让答案先接受五个小测验，再按失败项修复，留下可读的评测记录。

五个小测验先写通过条件

小测验输入情境通过条件
数字控制两份来源一致，收入 1000 对 800同比公式正确且保留两位小数
累计口径H1 与 Q1 同时出现说明 H1 是六个月累计，不生成未经来源支持的单季 Q2

来源冲突两份来源给出不同数值标记 conflict，停下并保留待复核
能力边界没有共识或公告原文不写 beat/miss、surprise 或确定性原因

主线

先看产品：业绩简报更新器

先把要交付的东西说清楚：一页教学用业绩简报，让读者看见收入、利润、同比、证据和未知项，并能回到原始材料复查。

主线第 1 步 · 定义产品与完成标准
查看完整提示词
我已解压并打开名为 byd_earnings 的文件夹。请先确认当前文件夹名称，并确认 output/byd_earnings_template.pptx 存在且可编辑；保留这个模板，不要删除或替换。

现在只做产品定义，不联网、不注册账号、不读取真实财务数据。在 data/evals/ 建立 product_spec.md，写清：
1. 使用者：需要快速阅读一家公司业绩变化的金融教师；
2. 任务：把一小组报告期数字整理成一页可核验的业绩简报；
3. 输入：本期、上年同期、单位、指标、来源和不确定项；
4. 输出：一页简报、变化率、来源说明、未知项和“需要人工复核”状态；
5. 完成标准：数字可复算，单位一致，来源可回查，证据不足时明确停下，不编造原因或共识比较。

同时建立 data/evals/README.md，写明本线使用的教学输入是虚构演示材料，不代表比亚迪或任何真实公司。完成写入测试后停止，不要建立真实数据目录。
主线边界

本步只定义产品和本地文件，不联网、不注册、不读取真实财务材料。

理解这一步

产品是“给谁解决什么问题、输入什么、输出什么、怎样算完成”的约定。本线先使用一个明确标注为教学输入的小数据集，不连接网络，也不把示例数字当成比亚迪事实；真实数据和自动化放在进阶扩展。

02
主线

跑一次 Chat 基线：先看它会怎样失败

先用一次普通 Chat 生成第一版简报。这个基线故意只解决“写出来”，把数字、单位和证据检查留到下一步，便于看见方法升级的必要性。

主线第 2 步 · 跑出第一版
查看完整提示词
请在当前 byd_earnings 文件夹内完成一次本地 Chat 基线，不联网、不使用真实财务数据。

先建立 data/evals/teaching_input.json，写入以下明确标注的教学输入：公司标签“教学用示例（非真实财务数据）”；本期“2026H1”；上年同期“2025H1”；单位“亿元”；营业收入 1000 对 800；营业利润 100 对 80；归母净利润 80 对 60；基本每股收益 1.20 对 0.90；来源“教学输入”。

然后只用这一份文件生成 output/brief_baseline.md。写出一页简报：标题、报告期、四项指标的本期/上年同期/同比、计算过程、来源和仍需核实的事项。文首写“教学草稿—未评测”，并注明这些数字不代表比亚迪或任何真实公司。不要添加市场反应、估值、评级、目标价或投资建议。完成后停止。
基线输入

data/evals/teaching_input.json 明确写着“教学用示例（非真实财务数据）”，它只用来比较方法。

理解这一步

基线不是最终答案，而是比较不同做法的参照物。输入文件会明确写“教学用示例（非真实财务数据）”；简报中必须保留草稿状态，不能把它发布成事实。

03
主线

用五个小测验找出失败点

把“看起来像对的”变成可以逐项检查的小测验。五个案例覆盖数字正确性、报告期口径、单位换算、来源冲突和能力边界。

主线第 3 步 · 运行五个评测
查看完整提示词
请在不联网的前提下，围绕 data/evals/teaching_input.json 建立并运行五个最小评测。把案例保存为 data/evals/cases.json，把通过条件保存为 data/evals/expected.md，把运行结果保存为 data/evals/eval_report.md。每个案例写清 input、pass_condition、observed、status 和 next_action。

五个案例固定为：
1. control：两份来源的本期和上年同期一致，收入同比应为 25.00%，通过条件是公式、单位和期间都写对；
2. cumulative：H1 是截至 6 月 30 日的六个月累计数，不得把 H1 减 Q1 写成未经来源支持的单季 Q2；通过条件是简报明确写“六个月累计”；
3. unit：一份来源用万元、另一份用亿元，换算后再比较；通过条件是换算因子和统一单位可复算；
4. conflict：两份来源数值冲突；通过条件是标记 conflict、停止下结论并保留待复核事项；
5. boundary：没有分析师共识或公告原文时；通过条件是不写 beat/miss、earnings surprise 或未经证据支持的原因。

先对 brief_baseline.md 做评测，再用简短的人工构造答案覆盖其余容易遗漏的情况。不要为了让结果全绿而修改输入或隐藏失败。完成后停止。
五个评测

数字控制 · 累计口径 · 单位换算 · 来源冲突 · 能力边界。通过条件先写，失败项留下。

理解这一步

评测先写通过条件，再看答案。每个案例只测一个容易出错的点；失败时留下原因和需要修复的地方。这里的“评测”是对产品输出的检查，不是让模型自己宣布通过。

04
主线

比较三种做法：Chat、固定 workflow、生成—评测—修复

把同一个产品放进三种做法中比较：一次 Chat、固定顺序的 workflow、以及“生成—评测—修复”循环。比较重点是可重复性、可检查性和失败时能否停下。

主线第 4 步 · 比较做法
查看完整提示词
请在当前 byd_earnings 文件夹内建立一个最小的本地方法对比，不联网，也不接入 Hithink 或巨潮。

在 workflow/minimal/ 建立 README.md、generate.md、evaluate.md、repair.md 和 run_log.md：
- README.md 对比一次 Chat、固定 workflow、生成—评测—修复三种做法，列出它们的输入、步骤、可见产物和失败时的停止条件；
- generate.md 只负责根据 data/evals/teaching_input.json 生成简报；
- evaluate.md 只负责运行 data/evals/cases.json 的五个评测；
- repair.md 只负责根据 eval_report.md 修复失败项；
- run_log.md 记录本次按“生成 → 评测 → 修复 → 再评测”的顺序运行了什么、每步状态和剩余人工复核项。

实际运行一次：以 brief_baseline.md 为起点，生成 output/brief_candidate.md，评测后生成 output/brief_repaired.md。修复只能使用教学输入和评测报告；保留失败记录，不把示例数字改成真实事实。完成后停止。
方法顺序

生成 → 评测 → 修复 → 再评测。每一步都有文件和状态，保留失败记录。

理解这一步

固定 workflow 规定角色和顺序；生成—评测—修复在每轮留下答案、评测和修复记录。两者都要复用五个小测验，评测结果由规则和人工检查共同确认。

主线

最后把最小闭环交付出来：一页候选简报、评测收据和人工复核清单。它已经是一个可演示的产品，真实数据接入可以沿同一接口继续。

主线第 5 步 · 交付最小产品
查看完整提示词
请运行 workflow/minimal 的最小闭环，以 data/evals/teaching_input.json 为唯一数字输入，以 data/evals/eval_report.md 为评测依据，生成：
1. output/finance_brief_candidate.md：一页候选简报，包含标题、报告期、指标表、本期/上年同期/同比、计算说明、教学输入来源、五个评测状态、未知项、下一步和“候选—需要人工复核”；
2. output/brief_review_checklist.md：逐项检查数字、单位、期间、来源、未知项和能力边界。

把披露事实、计算结果、可能解释、未知项分开；没有公告原文、分析师共识或真实数据时，不写 beat/miss、earnings surprise、投资建议或确定性原因。保留 brief_baseline.md、brief_repaired.md 和 eval_report.md，不覆盖它们。完成后停止。
主线交付物

output/finance_brief_candidate.md 是候选简报；它等待人工复核，不会自动发布。

理解这一步

候选意味着“可以阅读和复核”，不意味着自动发布。简报要把披露事实、计算结果、未知项和下一步分开；没有来源或共识输入的地方，明确写未知。

进阶第 2 步 · 生成候选 PPT

这是进阶扩展：在真实材料完整后继续。请分析比亚迪 2026 年半年报与 2025 年同期的收入与利润，金额统一为亿元，变化率保留两位小数；计算值明确标注。把结果保存到 data/case/prepared/income_profit_summary.csv。当前分析比较 2026H1 与 2025H1，均为截至 6 月 30 日的六个月累计数；不要用 H1 减 Q1 生成单季数。请使用起始包中已经存在的 output/byd_earnings_template.pptx，先确认它可打开且保留原有版式；若模板缺失或无法打开，保留现有材料并停止说明，不要自行换用其他模板。然后按这份模板建立 5 页大纲：第1页“封面与报告期”；第2页“收入与利润概览”，列营业收入、营业利润、归母净利润、基本每股收益的本期、上年同期和同比；第3页“增长与盈利能力”，放收入与归母净利润图表、收入增速、利润增速、营业利润率和归母净利率；第4页“本期主要变化”，只写有已核验数字或公告原文支持的收入、利润和解释；第5页“数据来源与核对”，列同花顺两份原始数据、巨潮摘要、巨潮全文和人工确认状态。营业成本在核对和来源材料中保留。巨潮摘要中的扣非归母净利润作为公告补充指标单列。资料不完整、报告期不清或单位无法统一时保留已取得材料并说明待补内容，不写结论。
